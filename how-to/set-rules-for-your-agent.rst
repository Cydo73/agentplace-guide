Set rules for your agent
========================

**Last checked:** |last_checked| against Agentplace's public documentation.

Use this guide to give your agent boundaries so it stays honest, stays on topic and knows when to stop.

Steps
-----

1. Decide the boundaries before you write rules. Ask what the agent may do alone, what needs the customer's confirmation, and what needs a person.

2. Write each rule as one plain sentence about one behavior.

3. Send the rules to the Builder in one message.

4. Test each rule with a question that tries to break it.

5. Publish again.

The rules and what each one prevents
------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Rule
     - What it prevents
   * - Use only the supplied listings and displayed prices.
     - Prices copied from other sites, and offers to book elsewhere.
   * - Check every item before answering a filtered question.
     - A confident answer based on the first few items found.
   * - Say how many matches you found.
     - A traveler thinking one result is the only one.
   * - Never call a result the only option unless the list is complete.
     - False claims of completeness.
   * - If something is missing, say so and ask for the link.
     - Invented listings, prices and policies.
   * - Give a draft plan with labelled assumptions.
     - A refusal to help just because dates are missing.
   * - Never assume what the traveler has not said.
     - Statements like "I am glad you are safe" before the traveler says so.
   * - For an emergency, safety advice comes first.
     - A booking answer to someone who is in danger.

A note on enforcement
---------------------

Wording in a rule is a request, not a lock. Agentplace advises that where approval is mandatory, you should build an enforceable workflow instead of relying only on what the prompt says. Use rules for behavior and connected workflows for anything that must always happen. See :doc:`Set up a handoff <set-up-a-handoff>`.
